================================================================================
                    TẦNG DTO (DATA TRANSFER OBJECT) LÀ GÌ? ĐỂ LÀM GÌ?
================================================================================

1. ĐỊNH NGHĨA:
- DTO là viết tắt của "Data Transfer Object" (Đối tượng dùng để vận chuyển dữ liệu).
- Đây là một Java Class (POJO) đơn giản, chỉ chứa các thuộc tính (fields), hàm khởi tạo (constructor), getter/setter và không chứa bất kỳ logic xử lý nghiệp vụ nào.

2. DTO ĐỂ LÀM GÌ? (MỤC ĐÍCH & VAI TRÒ):
- Vận chuyển dữ liệu giữa các tầng: Thường dùng để truyền dữ liệu giữa Client (Frontend / Postman / Mobile App) và Controller, hoặc giữa Controller và Service.
- Bảo mật thông tin (Bảo vệ Entity):
  + Tránh làm lộ các trường nhạy cảm trong Database ra ngoài (ví dụ: trường `password`, `resetToken`, `isDeleted`, v.v.).
  + Tránh việc người dùng gửi lên các trường không được phép thay đổi (Mass Assignment Vulnerability) như tự ý sửa `role = ADMIN` hay `balance`.
- Tối ưu hóa dữ liệu truyền tải:
  + Chỉ gửi/nhận những trường dữ liệu thực sự cần thiết cho từng chức năng, giảm kích thước payload mạng.
  + Ví dụ: Trang chủ chỉ cần hiển thị danh sách giày gồm (id, tên, ảnh, giá) -> không cần lấy toàn bộ mô tả chi tiết, ngày tạo, người sửa,...
- Xác thực dữ liệu đầu vào (Validation):
  + DTO thường kết hợp với Bean Validation (`@NotNull`, `@NotBlank`, `@Size`, `@Min`, `@Email`...) để kiểm tra tính hợp lệ của dữ liệu trước khi đi vào tầng Service.
- Tách biệt (Decoupling) cấu trúc CSDL và giao diện API:
  + Khi cấu trúc bảng trong Database (Entity) thay đổi, cấu trúc API trả về cho Frontend không bị ảnh hưởng nếu DTO vẫn giữ nguyên.

3. PHÂN LOẠI DTO PHỔ BIẾN TRONG DỰ ÁN SHOP GIÀY:
- Request DTO (Dữ liệu gửi từ Client lên Server):
  + UserRegisterRequest / RegisterDTO: username, email, password, confirmPassword, phone.
  + ProductCreateRequest / ProductDTO: name, price, brandId, categoryId, sizeIds, description.
  + OrderCreateRequest: address, phone, list of {productId, sizeId, quantity}, paymentMethod.
- Response DTO (Dữ liệu Server trả về cho Client):
  + ProductResponseDTO: id, name, price, brandName, imageUrl, availableSizes.
  + UserResponseDTO: id, username, email, fullName, role.
  + OrderResponseDTO: orderId, orderDate, totalPrice, status, items.

4. DÒNG DỮ LIỆU ĐI QUA DTO:
   Client (Gửi RequestDTO) 
      ---> Controller (Nhận RequestDTO, Validate) 
         ---> Service (Chuyển DTO thành Entity, xử lý nghiệp vụ) 
            ---> Repository (Lưu Entity vào Database)
   (Khi trả về: DB -> Repository -> Entity -> Service chuyển thành ResponseDTO -> Controller -> Client)
